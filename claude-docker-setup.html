Claude Docker — Setup Guide

Run Claude Code inside a Docker sandbox with your working directory mounted in and your credentials kept safely outside version control. Supports claude.ai subscription (OAuth), direct Anthropic API access, and a LiteLLM proxy.

Dockerfile run-claude-docker.sh claude-docker.env.template claude-docker-setup.html (this file) viewer/server.py viewer/viewer.html viewer/driver.mjs viewer/start-viewer.sh viewer/package.json

1 Get the files

Place Dockerfile, run-claude-docker.sh, and claude-docker.env.template together in a stable location — a dotfiles repo or a dedicated directory like ~/bin/claude-docker/ works well. The run script and Dockerfile are the only things you need to invoke day-to-day.

Note

All subsequent commands assume you are in the directory containing these files.

2 Set up credentials

Copy the template to your home directory and lock it down. This file holds API keys and should never be committed to version control.

bash 
cp claude-docker.env.template ~/.claude-docker.env
chmod 600 ~/.claude-docker.env

Open ~/.claude-docker.env in an editor and fill in your values:

  • ANTHROPIC_API_KEY optional Your Anthropic API key, obtained from console.anthropic.com. Only needed for --direct-api mode (per-token API billing). The default --direct mode uses OAuth via your claude.ai subscription and does not require this key.
  • LITELLM_URL required for --litellm Base URL of your organisation's LiteLLM proxy instance, e.g. https://llm.example.com. Ask your LiteLLM administrator for this.
  • LITELLM_API_KEY required for --litellm API key accepted by your LiteLLM instance. Ask your LiteLLM administrator.

Then add a line to your shell's startup file so the variables are available in every new terminal:

~/.zshrc or ~/.bashrc 
source ~/.claude-docker.env
bash — reload your shell config 
source ~/.zshrc   # or source ~/.bashrc

3 Make the script executable

bash 
chmod +x run-claude-docker.sh

4 Build the Docker image

From the directory containing the Dockerfile:

bash 
docker build -t claude-sandbox .

This installs Claude Code into the image. The build only needs to be re-run when the Dockerfile itself changes — not between sessions.

First launch — authentication

The first time you run the container in default (--direct) mode, Claude Code will walk you through a browser-based OAuth login with your claude.ai account. Follow the prompts in the terminal. Your credentials are saved into ~/.claude-docker/ and reused on all subsequent runs — you will not be prompted again unless the credentials expire.

If you use --direct-api instead, no interactive login is needed — Claude Code authenticates using your ANTHROPIC_API_KEY directly.

5 Install the viewer (optional)

The viewer is a full browser-based interface for Claude Code, not just a read-only mirror of the terminal. A small bidirectional driver (built on the Claude Agent SDK) runs inside the container and drives Claude directly — --viewer does not launch a terminal UI at all. You type prompts in the browser's own input box, approve or deny tool permissions there, and watch responses render live: streamed in token-by-token, thinking shown as its own bubble, syntax-highlighted diffs for file edits, and full markdown/KaTeX math.

Copy the whole viewer/ directory into your config directory and install its one dependency (the Agent SDK):

bash 
mkdir -p ~/.claude-docker/viewer
cp -r viewer/. ~/.claude-docker/viewer/
(cd ~/.claude-docker/viewer && npm install)

That's all — no image rebuild required. The run script bind-mounts ~/.claude-docker/ into the container, so the viewer files (and the node_modules the SDK needs) are available immediately at /home/claude/.claude/viewer/.

How it works

driver.mjs drives Claude through the Agent SDK's query() — one call per turn, threaded together via resume — and is the sole source of everything the browser shows: your prompts, Claude's text and thinking, tool calls, and permission requests. server.py is a plain broadcast relay that fans those messages out to connected browser tabs over Server-Sent Events and replays history for tabs that join late.

Re-copy after editing

If you ever modify the viewer files yourself, re-copy the directory into ~/.claude-docker/viewer/ and restart the container — editing your repo checkout alone has no effect on an already-running container, and neither Node nor the container's shell entrypoint hot-reloads.

6 Model selection (--litellm only)

When you launch with --litellm, an interactive model picker runs automatically before the container starts. No extra flag is needed. Two prompts are shown in sequence:

First, a numbered list of all models on your LiteLLM instance — select the primary model. Then a second prompt for the small/fast model used for Claude Code's background tasks (title generation, summaries). The small model defaults to "disable" on bare Enter, or you can choose "same as primary" or any other listed model.

    ...

Selections apply to the current session only. Use --list-models to preview what's available without launching.

Background model calls

If you select "disable" for the small model, DISABLE_NON_ESSENTIAL_MODEL_CALLS=1 is set automatically. If you pick a small model, it is passed as both ANTHROPIC_DEFAULT_HAIKU_MODEL and ANTHROPIC_SMALL_FAST_MODEL.

7 Launch

bash — common invocations 
# claude.ai subscription (OAuth), terminal UI — default
./run-claude-docker.sh

# Anthropic API key billing instead of subscription
./run-claude-docker.sh --direct-api

# LiteLLM — interactive model picker runs automatically
./run-claude-docker.sh --litellm

# Any provider + browser viewer (no terminal UI is attached in this mode)
./run-claude-docker.sh --viewer
./run-claude-docker.sh --litellm --viewer

# Viewer on a non-default port
./run-claude-docker.sh --viewer --viewer-port 7844

# List available LiteLLM models without launching
./run-claude-docker.sh --list-models

# Pass a flag through to claude (see Pass-through options below)
./run-claude-docker.sh --dangerously-skip-permissions

Run from whichever directory you want Claude to work in — it is mounted as /workspace inside the container.

Command-line options

Provider

FlagDescription
(default) / --direct Authenticate via your claude.ai subscription (OAuth). No API key required. On first run you will be prompted to log in via a browser; credentials persist in ~/.claude-docker/ for subsequent runs. Usage is billed to your Claude subscription, not an API account.
--direct-api Use the Anthropic API with an API key, billed per token to your Anthropic Console account. Requires ANTHROPIC_API_KEY. Claude Code connects to api.anthropic.com using its built-in default model.
--litellm Route requests through your LiteLLM proxy. Requires LITELLM_URL and LITELLM_API_KEY. An interactive model picker runs automatically before launch — no extra flag needed. See the Providers section for the full list of env vars set automatically.

Model selection (--litellm)

When using --litellm, an interactive model picker runs automatically before launch — no flag needed. You are prompted first for the primary model, then for an optional small/fast model for background tasks. Use --list-models to preview the available models without launching.

Utility

FlagDescription
--viewer Start the bidirectional browser viewer instead of the terminal UI. Opens http://localhost:VIEWER_PORT with Claude's responses rendered as markdown/math/ syntax-highlighted code and streamed live as they're generated. The browser's own input box drives Claude directly through a small Agent-SDK-based driver — no terminal session is attached at all. Requires viewer/ to be installed (with dependencies) in ~/.claude-docker/viewer/ — see step 5.
--viewer-port PORT Host port for the viewer's browser page and SSE feed. Default: 7843. Only meaningful with --viewer.
--viewer-driver-port PORT Host port for the bidirectional driver, which accepts prompts and permission responses from the browser. Default: 7844. Only meaningful with --viewer.
--help, -h Print a full usage summary and exit.

Pass-through options

Any flag not listed above is passed directly to the claude binary inside the container. Pass-through arguments are forwarded after all recognised flags have been consumed, so they can be freely mixed with the above. Examples:

FlagDescription
--dangerously-skip-permissions Disable Claude Code's interactive permission prompts. Only use this against repos you fully trust.
--print "prompt" Run non-interactively: send a single prompt, print the response, and exit. Useful for scripting.
--agent NAME Launch a specific subagent at startup.

Environment variables

All variables should be set via ~/.claude-docker.env (sourced in your shell startup file) rather than hardcoded in the script. The script validates that the required variables for the chosen provider are present before attempting to start.

  • ANTHROPIC_API_KEY optional — direct-api mode only API key for the Anthropic API, used only with --direct-api. Not needed for the default --direct (OAuth) mode.
  • LITELLM_URL required — litellm mode Base URL of your LiteLLM proxy, e.g. https://llm.example.com. Also used by --list-models.
  • LITELLM_API_KEY required — litellm mode API key for your LiteLLM instance. Also used by --list-models.

Providers

The script supports three providers. They are mutually exclusive per session; to switch you restart the container with a different flag. There is no way to change provider mid-session within Claude Code itself.

Subscription OAuth (default / --direct)

Authenticates using your claude.ai account via an OAuth browser flow. No API key is required. On first run, Claude Code will print a URL and wait for you to log in; after that, the credentials stored in ~/.claude-docker/ are reused automatically. Usage is billed to your Claude subscription (Pro, Team, or Enterprise) rather than to a per-token API account.

Direct API key (--direct-api)

Sends requests to api.anthropic.com using an API key from console.anthropic.com, billed per token to that account. No interactive login is required. Claude Code uses its own built-in default model; no base URL or model override is set.

LiteLLM proxy (--litellm)

Routes all requests through your organisation's LiteLLM instance, which can serve multiple model backends under a single endpoint. Because Claude Code is designed for Anthropic's API, the script sets several env vars automatically to make it work correctly:

  • ANTHROPIC_BASE_URL → your LiteLLM URL
  • ANTHROPIC_AUTH_TOKEN → your LiteLLM API key
  • ANTHROPIC_MODEL → your chosen model (if set)
  • ANTHROPIC_DEFAULT_HAIKU_MODEL + ANTHROPIC_SMALL_FAST_MODEL → your picked small model (if chosen)
  • DISABLE_NON_ESSENTIAL_MODEL_CALLS=1 — suppresses background model calls when no small model is configured
  • CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS=1 — prevents beta headers some LiteLLM versions reject
  • DISABLE_TELEMETRY=1 — stops telemetry pings to Anthropic's servers

Use --list-models to preview what's available without launching. Model selection happens automatically at launch via the interactive picker.

LiteLLM route requirement

Claude Code speaks Anthropic's /v1/messages format exclusively — it does not speak the OpenAI-compatible /v1/chat/completions route. Your LiteLLM instance must have the /v1/messages (Anthropic-format) route enabled. See the smoke test section below to verify this.

Viewer

The viewer is a full browser-based interface for Claude Code — not a read-only mirror of a terminal session. It's an optional add-on (the run script works fine without it), but when enabled with --viewer, the browser is the interface: no terminal UI is launched at all.

How it works

Two processes run inside the container. driver.mjs is a small bidirectional driver built on the Claude Agent SDK — it drives Claude through the SDK's query() (one call per turn, threaded together via resume), and is the sole source of everything the browser shows: your prompts, Claude's text and thinking, tool calls, and permission requests. server.py is a plain broadcast relay: it fans driver.mjs's messages out to every connected browser tab over Server-Sent Events, and replays history to tabs that join or reconnect later. Neither process uses hooks or touches settings.json.

What you get

  • Live streaming — text and thinking render token-by-token as Claude generates them, not a replay of a finished message.
  • Thinking, shown separately — when the model thinks, it renders as its own distinct bubble rather than being hidden or folded into the response.
  • Real diffs for file edits — Edit/Write tool calls render an actual line diff, not a truncated one-line summary.
  • Tool-progress status — a status line above the input box shows "Thinking…" and ticks while long-running tool calls are in flight, similar to the terminal UI's own status line.
  • Permission & question cards — tool-approval prompts and AskUserQuestion requests render as interactive cards with Allow/Deny buttons or answer choices, right in the browser.
  • Sessions panel — switch conversations, start a new chat, archive/unarchive, rename, or delete sessions, all from the ☰ button.
  • Command palette — the / button lists slash commands available in the current session.
  • Settings panel — font size, content width, label size, status-line text size, light/dark theme, show/hide tool calls, and timestamp format, all persisted locally in the browser.

Installation

See step 5 — copy the whole viewer/ directory into ~/.claude-docker/viewer/ and run npm install there once, for the Agent SDK dependency. No Docker image rebuild is needed either way.

Sessions and the terminal UI

Because no terminal is attached, each --viewer launch generates a fresh, empty session by default. To continue an existing conversation, open the sessions panel (☰) in the browser and switch to it — this reloads that session's full history into the page.

Pinning a session at launch doesn't work yet

Passing --session-id, --resume/-r, --continue/-c, or --fork-session alongside --viewer starts the browser page but leaves it with no way to submit a prompt — the bidirectional driver isn't wired up for a session it didn't generate itself, and there's no terminal fallback to fall back to anymore. Use the sessions panel to switch sessions from within the browser instead of pinning one at launch.

Persistent state

~/.claude-docker/ on your host is bind-mounted into the container as /home/claude/.claude. This single directory holds everything Claude Code needs to persist between sessions:

  • settings.json — model picker entries, hooks, and other settings (including synced LiteLLM models)
  • .claude.json — OAuth credentials (subscription login), per-project trust decisions, personal MCP servers
  • Session history and conversation state

The directory is created automatically on first run. Back it up if losing your session history or settings would be disruptive.

LiteLLM smoke test

Before relying on --litellm for real work, verify that your LiteLLM instance has the Anthropic-format /v1/messages route enabled. Run this from your host (not inside the container), with your env file already sourced:

bash 
curl -s "$LITELLM_URL/v1/messages" \
  -H "x-api-key: $LITELLM_API_KEY" \
  -H "anthropic-version: 2023-06-01" \
  -H "content-type: application/json" \
  -d '{"model":"your-model-name","max_tokens":16,"messages":[{"role":"user","content":"hi"}]}'

A valid JSON response (even a short one) means the route is working. A 404 means the route isn't configured on the LiteLLM side — raise this with your LiteLLM administrator.

Beta header errors

Some LiteLLM versions reject the anthropic-beta headers that recent Claude Code versions send, returning an opaque HTTP 400. If you encounter this, ask your administrator to update LiteLLM, or add CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS=1 to your ~/.claude-docker.env as a workaround.
