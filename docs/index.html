PodPrompt

Run AI coding agents in a container and work with them in your browser — several at once, on two different backends, in different projects. The agents can message each other, hand each other work, and keep going while you are away.

What it is

PodPrompt gives you a browser window instead of a terminal. Inside a Docker container it runs coding agents — Claude Code or OpenCode, your choice, and both at the same time if you like — and streams everything they do to a web interface: their text, their thinking, every tool call, every file diff, every permission request.

The part that makes it unusual is that a session is not a dead end. Any session can list the others, send one a message, spawn a brand-new session to go do something, and read another session's transcript. You get a workspace of cooperating agents rather than one chat window.

Because that could obviously run away from you, the amount of work agents may do without your input is capped, and messages between them can be held for your approval. You decide how much rope to give.

The five ideas

Everything else in these docs is a detail of one of these. Read them once and the rest of the interface explains itself.

session

The unit of everything. A conversation with one agent, running on one backend with one model, in one directory. Sessions run concurrently and independently.

backend

Claude Code or OpenCode. Both appear in the same interface and are driven the same way, but they are not at feature parity — the docs flag each difference where you would hit it.

@handle

A session's address. How agents refer to each other. Follows a rename you make, and an old handle keeps resolving forever so nothing breaks mid-task.

mail

A message from one session to another. Delivered as a turn in the recipient. Sometimes held — for you to approve, or because the system is paused.

autonomy

One global budget of automatic turns, shared by every session. Spend it and everything parks until you say otherwise. Your input refills it.

Two kinds of child, and the difference matters

An agent can produce two different things that both look like "another session". A delegated session is a real session: it has a handle, you can open it, prompt it, and it outlives its parent. A sub-agent is the backend's own mechanism, lives inside its parent's turn, and appears in a roster rather than the session list — you can read it, but not talk to it.

Many sessions covers both.

Quickstart

Set up once, then run it from whichever project you want to work on. Assumes Docker and a Claude subscription or API key. Install & launch has the prerequisites, the credential options, and what each flag does.

once — put the command on your PATH 
export PATH="/path/to/podprompt/bin:$PATH"
once — build the image and install the viewer app 
podprompt --build
podprompt --deploy-viewer
whenever you want to work on something 
cd ~/some/project
podprompt

That opens http://localhost:7843 in your browser. The viewer is the default interface — there is no terminal UI unless you ask for one. Both ports bind to 127.0.0.1 only, so nothing is exposed to your network.

The directory you run it from becomes the workspace, mounted at /workspace for the agents to work in. That is how you choose a project — there is no project flag.
