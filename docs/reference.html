Reference

Every flag, every variable, every path, and a single table of every numeric default in the system.

Command-line options

Interface

--viewerBrowser interface with the bidirectional driver. The default — you do not need to pass it. Both backends are available per session.
--claude
--claude-code		A Claude Code terminal session instead, with no browser.
--opencodeAn OpenCode terminal session instead.

These are mutually exclusive. Combining two, or combining an explicit --viewer with a terminal backend, is a hard error.

Provider configures Claude Code

--directClaude subscription via OAuth, reading credentials from the mounted ~/.claude. The default. Needs a one-time terminal sign-in first.
--direct-apiAnthropic API key from ANTHROPIC_API_KEY, billed per token. No interactive login. Rejected with --opencode.
--litellmRoute through a LiteLLM proxy. Requires LITELLM_URL and LITELLM_API_KEY. Runs a model picker unless the interface is --opencode.
Gotcha · These are not actually enforced as exclusive

The usage text calls them mutually exclusive, but passing several does not error — the last one silently wins. Pass exactly one.

Image

--image NAMERun a different image instead of podprompt — a local variant built FROM podprompt with extra tooling. Must carry the org.podprompt.base label, which anything built on the base inherits automatically. Cannot be combined with --build. See A custom image.

Networking

--viewer-port PORTPort for the page and its event stream. Default 7843.
--viewer-driver-port PORTPort for the driver's control plane, which the page posts to. Default 7844.
--opencode-port PORTPort the OpenCode server listens on inside the container. Default 7845. Never published outside.
--opencode-v2-port PORTPort the OpenCode v2 server listens on inside the container. Default 7856. A separate program from the one above, with its own port. Never published outside.
--host-networkShare the host's network namespace; stop publishing ports and bind to loopback instead. For reaching host services that listen only on 127.0.0.1.
Do not set the viewer port to 7844

That is the driver's default port. Setting both to the same value makes the launcher publish it twice and the two services collide.

Utility

--buildBuild the podprompt Docker image from the checkout and exit. Works from any directory. Re-run after a Dockerfile or dependency change.
--deploy-viewerCopy the viewer app to ~/.local/share/podprompt/viewer/ and exit. Required before first use of the default interface. Works from any directory.
--list-modelsPrint the model ids your LiteLLM proxy offers, and exit. Needs LITELLM_API_KEY.
--help, -hPrint usage and exit.
These three find the checkout themselves

--build and --deploy-viewer resolve the checkout from the command's own location, following symlinks. You never need to cd back to it.

Pass-through

Anything the launcher does not recognise is appended to the underlying agent command — so --dangerously-skip-permissions, --print or --agent reach Claude Code, and --continue or --model PROVIDER/MODEL reach OpenCode. In the default browser mode there is no terminal agent to receive them, so they are reported and ignored.

Environment variables

Ones you set

Three, all optional depending on provider. The default subscription mode needs none of them. Put real values outside the repository — conventionally ~/.podprompt.env; podprompt.env.template shows the shape.

  • ANTHROPIC_API_KEY Required by --direct-api. Note that the template ships a literal placeholder, which counts as "set".
  • LITELLM_URL Required by --litellm and --list-models. Defaults to the literal placeholder <MY-LITELLM-URL>.
  • LITELLM_API_KEY Required by --litellm and --list-models.
Ports are flags, not variables

Setting VIEWER_PORT and friends in your shell has no effect — the launcher assigns them itself. Use the flags.

Ones that affect behaviour inside the container

  • PODPROMPT_YES Unset by default. Set to 1 to skip the confirmation prompt shown when the working directory is your home directory or an ancestor of it.
  • PODPROMPT_PERM_HOOK Defaults to on. Set to off to disable the hook that attributes a permission request to the sub-agent that raised it.
  • OPENCODE_DEBUG Unset by default. Turns on extra OpenCode backend logging.

The launcher also injects a set of variables the container needs — HOME, CLAUDE_CONFIG_DIR, the three ports, the bind address, the host workspace path, and the relevant ANTHROPIC_* values for your chosen provider. You do not set these; they are derived.

One LiteLLM side effect worth knowing

In LiteLLM mode, non-essential model calls are switched off unconditionally — including when you have picked a small, fast model for them. Telemetry and experimental betas are switched off too.

Ports & binding

ServicePortReachable from the host?
Page & event stream7843Yes, on 127.0.0.1 only
Driver control plane7844Yes, on 127.0.0.1 only
OpenCode server7845Never — loopback inside the container

Your browser loads the page from the first port, asks it where the driver is, and then talks to the driver directly. Nothing is bound to a routable interface in either networking mode.

Before launching, the launcher will clear a stale PodPrompt process off the viewer port — but only one it recognises as its own. An unrelated process is left alone and the launch aborts instead, telling you to pick a different port.

Where state lives

The container is recreated on every launch. Everything that persists does so because it is mounted from your machine.

On your machineHolds
~/.claude/ Claude Code credentials, settings, session history, per-project trust. Shared with a native claude install. Always mounted.
the directory you launch from Mounted at /workspace and used as the working directory. This is the project the agents act on.
~/.config/opencode/
~/.local/share/opencode/
~/.local/state/opencode/
~/.cache/opencode/		 OpenCode's own config, credentials, sessions, state and cache — plus the plugin that gives OpenCode sessions their messaging tools.
~/.local/share/podprompt/viewer/ The deployed viewer app. Replaced by --deploy-viewer. Its dependencies are not here — they are baked into the image.
~/.local/state/podprompt/ PodPrompt's own bookkeeping: the session tree, per-session preferences and model picks, pending approvals, autonomy policy, turn state, peers and the mail inbox.

Anything outside those paths is ephemeral. Rebuilding the image replaces the baked dependencies but touches none of your state.

How a backend is chosen

A session's backend is fixed for its lifetime. It is resolved in this order, first match winning:

  1. Whatever the driver already knows, for a session it has handled this run.
  2. An explicit choice from the caller — which is what + New chat always provides.
  3. The stored relationship record, for a child or delegated session.
  4. What the backends themselves report when their sessions are listed.
  5. Failing all of that, the last backend you deliberately chose for a new chat, and failing even that, Claude Code.
--claude and --opencode do not set a viewer default

They are terminal launch modes. They do not influence which backend a browser session uses — that comes from the picker.

Gotcha · OpenCode's tools depend on the plugin being deployed

OpenCode sessions get their messaging tools from a plugin that PodPrompt installs and points at the driver. A plain opencode run elsewhere on your machine is unaffected — the plugin is inert without the driver — and a hand-copied viewer that omits it leaves OpenCode sessions unable to message anyone.
