Using it

The interface

A guided read of everything on screen: the instruments in the header, the nine kinds of bubble, the controls above the composer, and every setting with the value it ships with.

The window

One scrolling column of full-width cards, with fixed furniture above and below it. Three panels slide in over the top when you open them, and a strip appears under the header only when something needs saying.

Three panels slide in over this, and are closed by default:

☰Sessions, on the left.
⚙Settings, on the right, in three columns.
↳The roster of this session's sub-agents, on the right.

The content column is 860px wide by default and the body text is 15px; both are sliders in settings, along with the theme. Everything in the feed is full width — speakers are not left/right aligned. Who is talking is carried by the label, its colour, and a faint tint on the body.

Header instruments

Left to right. Several are hidden until they have something to report.

Two bars, two colour schemes

The context bar has a green/amber/red progression. Plan usage has no middle tier — it is normal, then red at 70%. If you are reading them at a glance, they do not mean the same thing by the same colour.

Bubbles

Nine kinds. Each is a card with a coloured label; the label tells you who or what produced it.

BubbleWhat it is
You Something you typed. Rendered as Markdown.
Model The agent's reply, streamed token by token. Full Markdown: tables, blockquotes, syntax-highlighted code with a copy button per block, and maths. Hovering reveals a copy button for the whole message.
Thinking The model's reasoning, in subdued italics, streamed in place. Collapsed by default; can be shown or hidden entirely.
Tool A tool call and its result, with the tool's name in the label. Never rendered as Markdown — it is shown literally — though diffs and code inside it are highlighted. Shown by default, capped at 400px and scrollable.
Agent A sub-agent this session started. Carries the task title, a live status line, and a link into that sub-agent's own transcript.
Peer Mail that arrived from another session. Collapsed to a single line with a ▸ toggle, and the label links to the sender. A batch of mail is split so each sender gets its own bubble.
Delegation A session this one spawned, with live status. OpenCode differs — no live status there; read the nested session row instead.
Resume A dimmed, bodyless marker showing this turn was started automatically rather than by you. See Running unattended.
Approval An interactive permission or question card. Below.

Model names appear on Model bubbles only, unless you switch that to every bubble. Timestamps show the time only by default, and changing the format updates timestamps already on screen rather than only new ones.

The composer

Enter sends, Shift+Enter inserts a newline. The / button opens the slash-command palette. While a turn is running, Send becomes a red Stop and the box is disabled; the placeholder tells you what it is waiting for — your answer, your approval, an unavailable model, or a backend reconnecting.

The row above it carries the live turn indicator on the left, and four controls on the right:

ControlWhat it does
model Which model this session uses. Hidden until the list loads, or entirely if the backend has no such concept.
mode The agent or mode. OpenCode can switch these live.
Auto-approve Stops asking permission for tool calls in this session. Asks for confirmation when you switch it on, and goes bold amber while active.
Auto-deliver Lets mail arrive without waiting for your approval while you are watching. On by default for delegated sessions, off for everything else. See Sessions talking.
Gotcha · Auto-approve does not survive a restart

It is deliberately held in memory only. If the driver restarts, every session reverts to asking. Do not rely on it as the thing that keeps an overnight run unattended — use Always allow on the cards themselves, which the backend remembers.

The turn indicator reads Thinking…, then Thinking… (1,204 tokens), then Running `Bash`… (12s) with a ticking elapsed time once a tool is in flight.

Approvals & questions

These appear as cards inline in the conversation, where the request happened — not as a modal that interrupts you. The counter in the header tracks them across all sessions so one waiting in a session you are not looking at cannot go unnoticed.

Permission cards

ButtonEffect
AllowPermits this one call.
Always allowWidens the backend's own rules so calls like this stop asking in this session. Backend-dependent — the button only exists if the backend can do it.
DenyRefuses the call. The agent is told and carries on.

Always allow is the middle ground worth knowing about: narrower than Auto-approve, and unlike Auto-approve it persists. If a sub-agent raised the request but its card could not be filed in its own session, the card says so.

Question cards

When an agent asks you something directly, you get one block per question with fixed options as buttons, and option descriptions on hover. Some questions accept several answers; others replace your previous pick. Other… is always available and opens a free-text box — replacing the fixed choices on a single-answer question, adding to them on a multi-answer one. Submit stays disabled until every question has an answer.

Once answered, a card is replaced by what you chose: Allowed, Always allowed, Denied, or Answered: …. That resolution is stored by the driver, so it survives a reload and shows the same thing in a second tab.

If the driver restarts mid-request

Anything still waiting is reported in the transcript as abandoned, rather than quietly reappearing as though it were still live. A card whose request has since died is retracted on its own.

Load full history Claude Code only off Loads the complete transcript rather than a recent window. The OpenCode row is disabled, because it always loads everything anyway.
Gotcha · This one is not a browser setting, and it is asymmetric

It is stored by the driver, once per install, so it follows you between browsers rather than per tab. Switching it on reloads the page immediately. Switching it off only takes effect on the next load — the current feed is deliberately left alone rather than being emptied under you.

Autonomy

The third column holds one button that reads as a sentence describing what the system is currently doing. Clicking it opens a menu of choices rather than a set of fields. Fully covered in Running unattended.

Getting your attention

Off by default. Switching on Notify when a turn ends enables three channels at once, and asks the browser for notification permission. A sound can be layered on top.

  • The tab title always works, with no permission needed: ● for a finished turn, ✗ for a failed one, ? for a waiting approval or question. It clears when you come back.
  • An OS notification, when the browser allows it. Clicking it focuses the tab and switches to the session concerned.
  • A short beep, if you enable it.

Notifications only fire while you are away — the tab hidden, or the window unfocused. Approval and question notifications are sticky, because a blocked turn should not expire quietly. A finished turn may add that sub-agents are still running. If you have several tabs open, they agree among themselves so a turn is announced once.

Two deliberate silences

Your own Stop never notifies you — you know, you did it. And a turn is only announced by a tab that watched it start, so reconnecting or switching session mid-turn stays quiet rather than announcing a "finished" turn from replayed history.

Easy to miss

  • Jump to latest is at the top, not the bottom. It is the first item in the feed, so you reach it by scrolling up through a long transcript. The floating pill at the bottom is the other half of the pair, and appears when new content arrives while you are reading older material.
  • Session row actions are invisible until you hover, and a title is renamed by double-clicking it.
  • There is no global search, and no app-wide keyboard shortcuts. The / button is a slash-command palette for the composer, not a search box.
  • Auto-scroll only follows you when you are already at the bottom. Read something further up and new content will not yank you away.
  • Session families are collapsed by default, so a session that spawned others looks childless until you open the twisty.
  • A session's backend is fixed when it is created and cannot be changed afterwards from the interface.
  • Renaming to an empty title does nothing. A title cannot be cleared, only replaced.
